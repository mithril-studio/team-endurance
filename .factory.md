# Team-Endurance — notes for factory runs

A private training dashboard and coach on Intervals.icu. `web/` is Next.js, `backend/` is
FastAPI on PostgreSQL, `worker/` is a Cloudflare Worker, `ops/` is the VM scheduler fallback and
`deploy/` holds the systemd units, nginx config and live smoke tests. The README explains each.

The app runs at https://team-endurance.boxd.sh on one athlete's real data. A factory run never
touches it: it builds and tests here, and a human deploys from `main`.

## Setup

Run once, before anything else. Together about 30 seconds; pulling the Postgres image is most
of it.

```bash
docker run -d --name te-test-pg -p 127.0.0.1:65431:5432 -e POSTGRES_HOST_AUTH_METHOD=trust postgres:17
(cd backend && uv venv -q .venv --python 3.12 && uv pip install -q --python .venv/bin/python -r requirements.txt)
(cd web && npm ci --no-audit --no-fund)
(cd worker && npm ci --no-audit --no-fund)
```

The container is only for the backend tests. Production runs `postgres:17` too.

## Verify

Run the checks for every part you changed. All of them together take about a minute, so
running everything before the pull request is fine.

- backend: `cd backend && TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:65431/postgres .venv/bin/pytest -q`,
  then `.venv/bin/ruff check .`. Each test creates and drops its own schema, so reruns are safe.
  Without `TEST_DATABASE_URL` the tests connect as the OS user, a role the container does not
  have, and most of them error.
- web: `cd web && npm test && npm run typecheck && npm run build`
- worker: `cd worker && npm test`
- ops: `backend/.venv/bin/python -m unittest discover -s ops/tests`. It needs `httpx`, which
  the backend virtualenv has and the system Python does not.

Known failure on `main` (checked 2026-11-12):
`tests/test_jobs.py::test_unknown_scheduled_kind_is_acknowledged_not_retried`. `JobInput`
rejects the unknown job kind the test sends; the other 116 backend tests pass. Do not count it
against your change, and leave it alone unless the issue is about it.

## Rules

- No checks need a `.env`. Do not create one with real values, and never commit a secret.
- Schema changes go in a new numbered file in `backend/migrations/` (the next is `010_*.sql`).
  Never edit a migration that is already on `main`: the live database applied it by filename and
  will not run it again. Migrations run automatically when the API starts.
- Do not run `npm run test:e2e` (Playwright), `deploy/smoke.py` or `deploy/browser-smoke.mjs`.
  There is no browser here, and the smoke tests call the live app.
- Do not deploy: no `deploy/update.sh`, `deploy/bootstrap.py`, `deploy/publish-worker.py`,
  `wrangler deploy`, and nothing against the live VM.
